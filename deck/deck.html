Exact rule

The 10th failure inside any 60-second window bans. The count comes from stored timestamps, so a restart never loses or invents failures.

Exact expiry

A ban is active only while now < until, checked on every request by the ban gate. No cleanup job, no polling.

Our 2 improvements + demo

Better than the original for a college IT cell

1 · Escalating bans

The nth ban lasts n × the base duration, capped. A student who mistypes gets 60 s; a returning bot gets 2 min, 3 min, and so on. CrowdSec ships this switched off.

2 · Live admin dashboard

Active bans with live countdowns, one-click unban, an allowlist for shared college IPs, and the top attacking IPs. CrowdSec has no web UI in its repo.

Live demo: a bot sends 10 wrong passwords → banned on the 10th · a student keeps logging in → never blocked · the countdown hits 0 → ban lifted.
